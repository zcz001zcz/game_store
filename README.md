# Game Store Core

Тестовое backend-приложение: заказы на цифровые товары, идемпотентные платёжные
вебхуки, автоматическая выдача кода двумя поставщиками и восстановление после
неопределённого результата запроса.

Проект написан на PHP 8.3 без фреймворка. Небольшое HTTP-ядро, роутер и PSR-4-подобный
autoload находятся в `src/Core` и `bootstrap/autoload.php`. PostgreSQL одновременно
служит основной БД и надёжной очередью; Redis для этого объёма не требуется.

## Быстрый запуск

Требуется Docker с Compose v2.

```bash
docker compose up --build -d
curl --fail http://localhost:8080/health
```

Все параметры имеют безопасные dev-значения по умолчанию. Для переопределений
скопируйте `.env.example` в `.env` (`copy .env.example .env` в Windows CMD или
`cp .env.example .env` в Unix). `composer.lock` зафиксирован и используется
Dockerfile, поэтому чистая сборка устанавливает проверенные версии зависимостей.

Миграции применяются отдельным одноразовым контейнером до запуска API и worker.
Повторный запуск безопасен.

## Основной сценарий

Создать заказ (поле `order_id` необязательно; оно предусмотрено в том числе для
воспроизводимого сценария «вебхук раньше заказа»):

```bash
curl -sS -X POST http://localhost:8080/api/v1/orders \
  -H 'Content-Type: application/json' \
  -d '{"order_id":"ord_demo_001","sku":"STEAM-TOPUP-500"}'
```

Отправить платёжный вебхук:

```bash
curl -sS -X POST http://localhost:8080/api/v1/webhooks/payment \
  -H 'Content-Type: application/json' \
  -d '{
    "event_id":"evt_demo_001",
    "order_id":"ord_demo_001",
    "status":"paid",
    "amount":500,
    "currency":"RUB",
    "created_at":"2025-01-01T12:00:00Z"
  }'
```

Получить заказ и выданный код:

```bash
curl -sS http://localhost:8080/api/v1/orders/ord_demo_001
```

Каталог использует keyset pagination:

```bash
curl -sS 'http://localhost:8080/api/v1/catalog?limit=20&after_id=0'
```

## Тесты

Юнит-тесты (работает из Windows CMD/PowerShell):

```bash
docker compose exec -T api vendor/bin/phpunit
```

Полный интеграционный прогон также запускается одной кроссплатформенной командой:

```bash
docker compose exec -T api php tests/Integration/run.php
```

Локальные PHP, PostgreSQL, `make`, Git Bash и WSL не нужны. Runner выполняется
в уже запущенном контейнере `api` и обращается к сервисам внутри Compose-сети,
поэтому внешний `APP_PORT` может быть любым (например, `8081`) и повторная сборка
образа не требуется. При этом `PROVIDER_A_URL` и `PROVIDER_B_URL` должны оставаться
на внутреннем адресе `http://api:8080/...`: порт `8081` существует только на хосте.
Runner проверяет эту конфигурацию до изменения тестовых данных.

Он предназначен только для `APP_ENV=dev/test` и выполняет восемь
детерминированных сценариев:

- создание изолированной выборки из 2000 SKU и 50 параллельных чтений страницы по 100 товаров;
- 50 одинаковых и 50 разных параллельных платёжных вебхуков;
- определённый отказ A и безопасный fallback на B;
- таймаут A после выдачи и повтор с прежним `request_id` без вызова B;
- `out_of_stock` и последующее безопасное восстановление;
- переход `delivery_failed → delivered` именно фоновым сервисом `recovery`, без ручного endpoint;
- два вебхука до появления заказа и их воспроизведение по времени события;
- обнаружение сверкой четырёх контролируемых классов несогласованности.

Каждый сценарий проверяет не только HTTP-статус, но и инварианты непосредственно
в PostgreSQL: одну денежную проводку, одну задачу, одну выдачу и один расход кода.
Тестовые заказы используют префикс `ord_it_`, а изолированные товары и ключи —
`ITEST-`. Результаты текущего запуска остаются для диагностики, а перед следующим
запуском только эти тестовые данные очищаются. Поэтому прогон не зависит от уже
израсходованных демонстрационных ключей. Намеренно неконсистентные записи сценария
сверки удаляются сразу после его проверки и не остаются в БД.

На Unix по-прежнему доступны отдельные shell-сценарии через `make test-race`,
`make test-fallback`, `make test-timeout`, `make test-stock` и
`make test-ordering`. Полный Docker-runner можно вызвать как `make test-integration`.

## Управляемые заглушки поставщиков

В `APP_ENV=dev` поведение A/B можно сделать детерминированным:

```bash
curl -sS -X PUT http://localhost:8080/api/v1/dev/providers/A \
  -H 'Content-Type: application/json' \
  -d '{"mode":"timeout_after_issue","failure_rate":0,"timeout_rate":0,"timeout_ms":1500}'
```

Режимы: `random`, `success`, `fail_before_issue`, `timeout_after_issue`,
`out_of_stock`. В `random` используются настраиваемые `failure_rate` и
`timeout_rate`. Повтор с тем же `request_id` всегда возвращает тот же код.

## Сверка и восстановление

```bash
curl -sS http://localhost:8080/api/v1/ops/reconciliation

curl -sS -X POST http://localhost:8080/api/v1/ops/recovery \
  -H 'Content-Type: application/json' \
  -d '{"order_id":"ord_demo_001"}'
```

Сервис `recovery` также периодически и безопасно возвращает зависшие заказы в
очередь. Повторная постановка не создаёт вторую задачу благодаря уникальному
`dedup_key`.

## Ключевые решения

- Деньги хранятся целым числом в минимальных единицах (`price_minor`), без `float`.
- `payment_events.event_id` — первичный ключ; повтор события не меняет состояние.
- Денежная проводка уникальна по `(order_id, entry_type)`.
- Переход в `paid`, проводка и задача выдачи фиксируются одной транзакцией.
- Очередь — таблица `jobs`; захват выполняется через `FOR UPDATE SKIP LOCKED`.
- На заказ существует один `dedup_key`, одна строка `fulfillments` и один код.
- После таймаута попытка остаётся `uncertain`. Worker повторяет того же поставщика
  с прежним `request_id`; fallback разрешён только после определённого ответа,
  гарантирующего, что A ничего не выдал.
- Ранний вебхук хранится в `pending` и воспроизводится при создании заказа.
- `paid` является монотонным фактом: запоздалый `failed` не откатывает оплаченную
  или уже выданную покупку.

## Фактически затраченное время

Около **6 часов суммарно**, распределённых на несколько коротких сессий. В оценку
включены анализ задания и проектирование, реализация, диагностика состязательных
сценариев, финальный прогон и документация. Подробности: [docs/time-log.md](docs/time-log.md).
